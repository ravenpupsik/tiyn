# ТЗ: репозиторий Tiyn на GitHub (classic + glina в одном репо)

Исполнитель: Мастер. Автор: Критик. Дата: 14.11.2026.

## 1. Цель
Один репозиторий на GitHub, где лежат обе версии Tiyn. Каждая версия остаётся отдельным Flutter-проектом и собирается сама. Код в одно приложение НЕ сливаем.

## 2. Структура
```
tiyn/
  classic/        ← /workspace/tiyn_classic/money_app (основная, D:\androidproject\money_app на ноуте)
  glina/          ← /workspace/tiyn_glina/money_app_glina (v1.0.0+7)
  docs/           ← ТЗ: TZ_days.md, TZ_backup.md, TZ_repo.md (по желанию, без скриншотов с реальными суммами)
  .gitignore      ← общий, корневой
  README.md
```
- Папка `shared/` сейчас НЕ нужна. Вынести общий код (формат бэкапа) в локальный пакет можно потом, отдельной задачей.
- Вложенных `.git` быть не должно. В `classic/` уже есть пустой `.git` без коммитов, его удалить. Сабмодули не использовать.
- Ветки: одна `main`. Ветки «classic/glina» вместо папок не делать.

## 3. Источник правды
- Главная копия classic — на ноуте Аблайхана (`D:\androidproject\money_app`). Перед заливкой сверить её с копией на коробке и взять самую свежую. Если они расходятся, спросить Аблайхана, а не перетирать молча.
- Glina берём с коробки, v1.0.0+7.

## 4. Что НЕ должно попасть в репо (обязательно)
Корневой `.gitignore` = стандартный Flutter + дописать:
```
**/build/
**/.dart_tool/
**/.flutter-plugins-dependencies
**/android/local.properties
**/android/key.properties
**/android/app/upload-keystore.*
*.jks
*.keystore
*.iml
.idea/
tiyn_backup_*.json
data_backup/
```
- Ключ подписи и `key.properties` никогда не коммитить. Ключ хранится только на ноуте, плюс отдельная копия вне репо, например в облаке у Аблайхана. Если ключ потеряется, обновлять Tiyn поверх установленного станет невозможно.
- Реальные бэкапы с тратами не класть. Тестовые фикстуры (`classic/test/fixtures/glina_backup.json`) можно: там выдуманные данные. Проверить это перед коммитом.
- Перед первым коммитом выполнить `git status` и `git ls-files | grep -Ei "jks|keystore|key.properties|backup"`. Результат должен быть пустым, кроме фикстур.

## 5. Репозиторий на GitHub
- Имя: `tiyn`.
- Видимость: приватный по умолчанию. Публичный — только если Аблайхан сам скажет (например, для портфолио), и тогда ещё раз проверить секреты.
- Создаёт и пушит Аблайхан со своего аккаунта, или Мастер, если у него есть доступ. Токены в репо и в чат не вставлять.
- Первый коммит: `chore: init monorepo (classic + glina)`. Дальше коммиты маленькие, с префиксом папки: `classic: settings screen`, `glina: fix widget`.

## 6. README.md (коротко)
- Что это: Tiyn, учёт денег, Flutter.
- Две версии: `classic` (основная, Doto, красный) и `glina` (редизайн «Глина»). У обеих один applicationId `com.moneycash.money_app`, поэтому на телефоне одновременно стоит только одна.
- Сборка: `cd classic && flutter pub get && flutter build apk --release`, то же для `glina`.
- Важно: при смене версии versionCode должен расти, а данные (SharedPreferences) сохраняются. Перед переустановкой сделать бэкап в Настройках.
- Бэкап `.json` (app:"tiyn", version:1) совместим между версиями.
- 2–3 скриншота можно, но без реальных сумм.

## 7. Не делаем
- Не сливаем classic и glina в одно приложение и не делаем переключатель стилей.
- Не делаем CI/GitHub Actions, релизы и теги — это позже, по желанию.
- Не трогаем код приложений, это чисто упаковка.

## 8. Проверка готовности
1. После `git clone` в пустую папку каждая из `classic/` и `glina/` проходит `flutter pub get` и `flutter build apk --debug`.
2. В репо нет ключей, `key.properties`, `local.properties`, `build/`, реальных бэкапов (проверка из п.4).
3. Ссылка на репо и вывод `git ls-files | head -50` отправлены Аблайхану.
4. Ключ подписи лежит на ноуте и в резервной копии вне репо, Аблайхан это подтвердил.
